# Дипломный проект — Яндекс.Самокат (ручное тестирование)

## Описание проекта
Комплексное тестирование веб- и мобильного приложения **Яндекс.Самокат** — сервис аренды электросамокатов. Дипломный проект курса «Инженер по тестированию: от новичка до автоматизатора».

Проект состоит из **двух частей**: тестирование веб-приложения и тестирование мобильного приложения.

## Задачи

### Задание 1. Веб-приложение
1. Составить чек-лист по требованиям к экрану «Статус заказа».
2. Составить проверки валидации полей экрана «Сделать заказ».
3. Провести тестирование всей функциональности по чек-листам, таблицам и макетам.
4. Завести баг-репорты на найденные дефекты.
5. Проверить статусы заказа по инструкции.

### Задание 2. Мобильное приложение
1. Спроектировать тест-кейсы на выделенную функциональность.
2. Написать кейсы на вёрстку по макетам Figma.

## Что сделано

### Веб-приложение

#### 1. Чек-лист «Статус заказа»
Составлен чек-лист из **74 проверок**, сгруппированных по блокам:
- Вёрстка и элементы экрана.
- Оформление заказа и переход к статусу.
- Номер заказа и поиск.
- Данные заказа.
- Статусы заказа.
- Отмена заказа.
- Просроченный заказ.
- Просмотр другого заказа.

#### 2. Таблица валидации полей
Составлены проверки валидации для полей формы «Сделать заказ»:
- **Имя** — 2–15 символов, только русские буквы, тире, пробел.
- **Фамилия** — 2–15 символов, только русские буквы.
- **Адрес** — 5–50 символов.
- **Станция метро** — выбор из саджеста.
- **Телефон** — 11 цифр с 8 или 12 символов с +7.
- **Дата доставки** — только с завтрашнего дня.
- **Срок аренды** — 1–7 суток.
- **Комментарий** — 0–24 символа.
- **Цвет** — один или оба цвета.

Для каждого поля применены **классы эквивалентности и граничные значения**.

#### 3. Баги вне тестовой документации
Найдено **13 дополнительных багов** на главной странице и в других местах:
- Название самоката на главной отображается неверно.
- Вопросы FAQ не сворачиваются после раскрытия.
- Порядок вопросов FAQ отображается неверно.
- Оформление раскрытых вопросов FAQ некорректно.
- При ошибке поиска заказа отображается неверное изображение.
- Лишняя кнопка «GO» на экране поиска.
- Неверный плейсхолдер поля «Адрес».
- Слишком тёмный плейсхолдер «Станция метро».
- Нет кружка с цветом линии метро.
- Кнопка перехода ко второй части названа «Далее» вместо «Дальше».
- Кнопка «Хорошо» близко к сообщению.
- **Критический:** кнопка «Да» не нажимается в Google Chrome.
- Лишнее окно подтверждения заказа.

### Мобильное приложение

#### 1. Тест-кейсы на функциональность
Составлено **14 тест-кейсов** для двух блоков:

**Пуш-уведомления (ТК-НОТ-01 — ТК-НОТ-09):**
- Отсутствие уведомления в 21:58.
- Появление уведомления в 21:59.
- Отсутствие уведомления в 22:00.
- Содержание уведомления о двух часах до окончания заказа.
- Переход во вкладку «Мои» по уведомлению при активном/фоновом/закрытом приложении.
- Отсутствие уведомления при запрете.
- Появление уведомления на заблокированном экране.

**Отсутствие интернет-соединения (ТК-ИНТ-01 — ТК-ИНТ-06):**
- Появление уведомления об отсутствии интернета.
- Закрытие по кнопке «Ок».
- Невозможность закрытия тапом вне кнопки.
- Повторное появление при сохраняющемся отсутствии связи.
- Отображение с заголовком, текстом и кнопкой.
